# 通用且正确的积分机制：可行性与方法评估（2026-09-12）

> 本文评估「不靠规则枚举，而靠定理驱动的机制」这条路线的可行性、方法论与代价。
> 结论基于三处证据：本仓库代码与模块文档的事实、0.27.3 调研的量化数据
> （见 [BENCHMARK_RESULTS_CN.md](BENCHMARK_RESULTS_CN.md) §「0.27.3 后续调研」）、
> 以及公开文献的算法成熟度。凡属估算都在文中标注。

---

## 1. 先把判据定清楚

| 概念 | 操作性定义 |
|---|---|
| **通用** | 输出由**定理覆盖的参数化族**给出，而非逐例模式；代码量与被覆盖输入族的规模**脱钩**（Rubi 的 6700 条规则恰好相反） |
| **正确** | 每个输出都带**可机检的证明**（微分域内的符号证书 `D(F) − f ≡ 0`），而不是抽样数值验证；错误答案在结构上不可能流出 |
| **完整（相对）** | 对已实现的扩张片段，算法是**判定过程**：要么给出原函数，要么**证明**非初等 |
| **诚实** | 输出三值化：`Found` / `ProvedNonElementary` / `Unknown`；当前 oCAS 把后两者统一混为「回退」，这是信息损失 |

「通用且正确」不等于「覆盖一切」：它意味着**你实现了什么片段，那个片段就是判定过程且结果可信**。
覆盖率是单独的工程问题，不该靠牺牲正确性来换（0.27.2 的六组错案就是教训）。

## 2. 理论骨架：算法已存在，且是判定过程

- **Liouville 定理 + Risch 算法**：给定初等超越扩张上的初等函数，判定其原函数是否初等，并在初等时构造之。
  **通用性与正确性由定理保证**，不需要逐例人工验证。
- 教科书级的完整阶梯（Bronstein, *Symbolic Integration I*，含伪码）：

| 章 | 内容 | oCAS 现状 |
|---|---|---|
| ch. 2 | 有理函数：Hermite 约化 + Rothstein–Trager | ✅ `integral/rational.rs` |
| ch. 3–5 | 初等超越扩张（primitive `log` / hyperexponential `exp`） | 🟡 部分（见 §3） |
| ch. 6 | Risch 微分方程 `Dq + fq = g` 与耦合系统 | 🟡 **仅多项式解**（`integral/rde.rs` 文档自陈） |
| ch. 7–8 | **代数扩张**与正则塔（Trager 积分基） | ❌ 未接（因式分解已有，见 §3.5） |
| ch. 9 | 并行 Risch / 结构定理的工程化 | ❌ |
| （非初等） | Singer 结构定理；工程上最通用的可判定路径是 **Meijer G / Slater 展开**（SymPy `meijerg` 路线）或 **holonomic（Gosub–Zeilberger 风格）**；对数情形是 **Li₂（二重对数）归约**（Lewin 公式 + Raab/Baddoura 的算法化） | ❌ |

**关键判断**：这条路线的理论成熟度是「教科书 + 已发表算法」级别，不是研究前沿；
真正的难点在**工程规模**与**复杂度控制**，不在「有没有算法」。

## 3. oCAS 已有的基石与缺口（全部来自代码/文档，非推测）

### 3.1 已有（这是「可行性高」的主要理由）

- **微分塔** `ℚ(x, t₁, …, tₙ)`：`tower/build.rs` 的 `GenKind::{Constant, Log, Exp}` + 每个生成元的导数、`tower/convert.rs` 的 Atom ↔ 塔元素双向转换。
- **塔元素代数**：`tower/elem.rs` 的 `KElem`（域元素）、`KPoly`（顶层生成元多项式 + 下层系数）、`KRat`，含 `derivative_dt`、`div_rem`、`gcd`、`eea`、`square_free`、`partial_deriv` —— 即 Risch 需要的全部域运算。
- **Risch 递归**：`integral/risch.rs` 逐层下降（每层 Hermite 约化 / 对数导数恒等式 / primitive 层未定系数 / hyperexponential 层 `rde.rs` / 基层委托 `rational.rs`）。
- **代数数域**：`ocas-poly/src/factor/algebraic.rs` 已实现 **Trager 算法**（范数 = 求值–插值结式、Trager 平移保证无平方、ℚ 上因式分解 + K 上 GCD 还原）——这正是代数情形所需的核心工具。
- **模算法**：0.25 的 `MultiModular ℚ` 管线（并行幸运素数 + CRT + 有理重构 + 无迹 Hensel）——解决**符号系数下的系数爆炸**（当前 12 例超时中 9 例挂在 `symbolic_rational`）。
- **可验证性基础设施**：0.27.2/0.27.3 的数值 oracle（`ocas-tests/src/integral_eval.rs`）、1892 harness、SymPy 对拍、proptest、`preserves_argument_order` 语义护栏。

### 3.2 缺口一：代数生成元被直接拒绝

`tower/build.rs` 文档：「algebraic functions such as `√x` (non-integer exponents) are rejected」。
后果：整个 **radical 桶（356 例未解，占最大桶之一）**与代数扩张族进不了通用引擎。

### 3.3 缺口二：依赖生成元被拒绝而非合并（影响面已实测）

`tower/build.rs` 文档：「algebraically dependent generators (e.g. `log(x)` and `log(2x)`, or `exp(x)` and `exp(x+1)`) are rejected rather than merged」。

这条的实测影响被严重低估：三角/双曲在进入 Risch 前会被改写成指数，
于是 `sinh(u) = (eᵘ − e⁻ᵘ)/2` 必然产生 `exp(u)` 与 `exp(−u)`，而 `eᵘ·e⁻ᵘ = 1` 是**代数相关** → 整族被拒。
**实测：111 例未解题（7.3%）含双曲函数**（mixed-other 76 + hyperbolic 35）。
0.27.x 的 `hyperbolic_reduction.rs`、`kernel_subst.rs`、`exp_log.rs` 在相当程度上就是**在绕这个限制打补丁**——
即：先补丁机制，而没有修通用引擎的入口条件。

### 3.4 缺口三：RDE 只求多项式解

`integral/rde.rs` 文档明说只找多项式解，有理解（需要分母界）超出片段。
后果：`exp` 层的相当一部分积分被放弃（spec 上属于 Bronstein ch. 6 的完整版）。

### 3.5 缺口四：代数扩张上的积分链未接

Trager **因式分解**已有，但缺少：积分基（integral basis）、代数 Hermite 约化、代数留数、
正则塔的构造。这是 ch. 7–8 的正题，也是 `1/(1+x⁴)`、`1/(1−3x²+x⁴)`、不可约六次分母等**整族**的钥匙
（0.27.3 探针已确认这些全部回退，且 SymPy 自身对其中若干返回 `RootSum`）。

### 3.6 缺口五：无非初等判定，且缺函数头

- 无 Meijer G / Li₂ 归约，连 `polylog`/`Li₂` 函数头都不存在。
- **实测：122 例未解（8.0%）的参考答案含 `polylog`** → 今天**不可达**，与机制质量无关。
- 由于没有非初等判定，引擎无法区分「已证明非初等」与「我不知道」，用户拿到的是同一个 `Integral(...)`。

### 3.7 缺口六：复杂度而非预算是瓶颈

9/12 例超时挂在 `symbolic_rational`。这是**符号系数下域欧几里得的系数爆炸**，
属于算法复杂度问题；0.27.x 反复「加预算/加闸门」只是把它变成快速拒绝（诚实但不解决问题）。
正确方向是模算法（已有 MultiModular）+ 并行 Risch + 惰性级数，而不是继续调墙钟。

## 5. 方法：把「正确」变成纪律，把「通用」变成递归

1. **统一接口，结构性递归**：`trait RischIntegrate`（每个扩张类型一个实现：primitive / hyperexponential / algebraic），
   递归沿塔下降。禁止用模式匹配替代结构定理——那是退化成 Rubi。
2. **证书优先（本评估最重要的一条）**：
   每个输出的验收标准是**符号**证书 `normalize_in_field(D(F) − f) == 0`；
   数值 oracle 降级为「探测 + 回归」工具。只有这样，「正确」才不依赖人工审查每一条规则。
3. **三值 Outcome 贯穿全链**：`Found { value, certificate }` / `ProvedNonElementary { witness }` / `Unknown`；
   `Unknown` 必须诚实返回 `Integral(...)`，不得伪装。
4. **正则塔**：合并代数相关生成元（而不是拒绝）；相关但**无法判定**时返回 `Unknown`。
5. **代数情形复用现有资产**：定义多项式 → 积分基（Trager）→ 代数 Hermite → 留数；`ocas-poly` 的
   Trager 因式分解与结式直接可用。
6. **非初等层分两步走**：先补函数头 + oracle 数值核验（0.27.3 已验证此模式：`Ei`/`Si`/`Ci`/`Shi`/`Chi`/Fresnel
   都是这样落地的），再补归约（Li₂ → Meijer G）。
7. **性能靠算法不靠预算**：模算法（MultiModular）+ 并行 Risch + 惰性级数；墙钟预算只用于**防御**，
   不用于掩盖复杂度。
8. **通用性测试是新指标**（不能只跑 Rubi 题库）：
   - proptest 从**塔**随机生成元素（而非从语法随机生成字符串）→ 积分 → **符号证书**校验；
   - 对抗族：依赖生成元、分支/定义域退化、参数退化（如 `m = −1` 使公式失效）；
   - 新指标 **`certified_rate` = 证书通过数 / 已解数**，目标恒为 `1.0`，作为 CI 门禁。
9. **实值语义单独标注**：证书是形式（微分域内）的；分支/定义域需要符号层之外的处理
   （`halfpower` 的片层因子就是先例），必须显式记录而不能默认「形式正确 = 实值正确」。

## 6. 分阶段路线与验收门

**版本映射（2026-09-12 已写入 ROADMAP / EVOLUTION_PLAN）**：P0→**0.28.0**、
P1→**0.29.0**、P2→**0.30.0**、P3→**0.31.0**、P4→**0.32.0**；
原 0.28.0/0.29.0/0.30.0（Gröbner 大规模性能、LLVM JIT、矩阵引擎 + 平台收尾）
依序顺延为 **0.33.0/0.34.0/0.35.0**，1.0.0 顺延至第 69 月。
0.27.3 已定位的两个**缺陷**（残项解析、表达式级循环检测）并入 0.28.0 一起交付。

| 阶段 | 版本 | 交付 | 验收门（用现有 harness + 新指标） |
|---|---|---|---|
| **P0** | **0.28.0** | 缺陷修复（残项解析 + 表达式级循环检测）+ 符号证书 + 三值 `Outcome` + 依赖生成元合并 | 1892 已解集合的证书 100% 为 0；`certified_rate = 1.0`；双曲族新增可解数（实测基线 111 例未解）；超时数不上升 |
| **P1** | **0.29.0** | 补全超越 Risch（RDE 有理解 + 耦合系统 + 对数部分结构定理） | `exp-log` 桶显著改善；**0 回归**；证书门保持 |
| **P2** | **0.30.0** | 代数扩张（正则塔 + 积分基 + 代数 Hermite + 留数）+ 多根式基 + 反函数代换引擎 | `1/(1+x⁴)`/`1/(1−3x²+x⁴)` 族可解；radical 桶与 `inverse-trig-hyper` 桶改善；证书门保持 |
| **P3** | **0.31.0** | 非初等层（`polylog`/`Li₂` 头 + oracle + Li₂/Meijer 归约 + `ProvedNonElementary`） | 122 例 `polylog` 中的可及部分；`exp-log` 剩余；证书门保持 |
| **P4** | **0.32.0** | 性能（模算法 + 并行 Risch + 惰性级数） | 墙钟不超过 0.28.0 基线；超时数下降 |

顺序理由：P0 是**零数学风险的前置**（且立刻给出「正确」的硬不变量）；P1 复用最多现有代码；
P2 复用 Trager 资产；P3 风险与工作量最大但收益最独有（8% 的题今天完全不可达）；
P4 放在能力之后，避免用性能预算掩盖能力缺失。

## 7. 诚实的限制与风险

1. **规模**：Bronstein 全书是研究级篇幅，完整 Risch 按**人年**计。因此必须**按片段交付**，
   并始终保持「**不发射未认证结果**」这一硬不变量——能力可以渐进，正确性不能渐进。
2. **不可判定点**：塔中常量识别、代数相关性判定在一般情形不可判定 → 必须 `Unknown` 而不是猜。
   这与调试期不需要「更高覆盖率」，而需要「零错案」一致。
3. **实值分支**：微分域证书不能保证实值原函数在指定区间上正确（对数分支、`|p+q|` 类）。
   需要额外的定义域/片层处理与文档化。
4. **性能**：完整 Risch 慢；Symbolica 的 Rubi 移植在 1892 上比 oCAS 快约 4.1×。
   因此架构应是**通用引擎作正确性主干 + 规则/启发式作快速路径**，且**两者都必须认证**。
5. **与规则路线的关系**：本路线不排斥规则层，但规则层必须排在机制之后（见
   [GAP_ANALYSIS_CN.md](GAP_ANALYSIS_CN.md) §7.3），否则又会退化成枚举方案。
6. **与 0.27.3 缺陷的关系**：`GAP_ANALYSIS` §7.3 第 4 点的第 1–2 项（残项解析、表达式级循环检测）
   是**缺陷**而非能力，应先修（第 1 项已有实测净 +4），它们与本文的 P0 互不冲突。

## 8. 结论

- **可行性：高**。理论是教科书级的判定过程；oCAS 已具备塔、域运算、RDE、有理积分、
  Trager 因式分解、模算法、oracle 与 harness——即**过半基石**。缺的是把代数情形接上、
  把保守拒绝（依赖生成元、有理解）放开、以及补一个非初等层。
- **方法：定理驱动的结构性递归 + 证书化的正确性纪律 + 独立的通用性指标**。
  这三条缺一不可：只有递归会退化，只有证书会没有能力，只有题库会过拟合。
- **代价**：按片段交付的多年工程，但每一片交付都**立刻**带来可测的覆盖与永久性的正确性收益，
  且不与 LGPL 生态位冲突（全部自研实现，算法本身不受版权限制）。
- **不做什么**：不用规则枚举替代结构定理；不用墙钟预算掩盖复杂度；不在无证书的情况下扩大发射面。
